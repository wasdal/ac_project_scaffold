# Guide for AI Coding Assistants

This document explains how the coding agent is expected to work in this repo.

## Repository Structure

```
/
├── AGENTS.md                # Instructions for coding agents.
├── specs/                   # System specification (what to build).
│   ├── vision.md            # Vision of the System.
│   ├── scope.md             # Scope of the System.
│   ├── architecture/        # Architectural specifications.
│   │   ├── principles.md    # Architectural principles to follow.
│   │   ├── layers.md        # Architectural layers.
│   │   ├── components/      # Specifications for each architectural component.
│   │   ├── quality/         # Specifications for quality attributes.
│   ├── domain/              # Domain model specifications.
│   ├── requirements/        # System requirements.
│   │   ├── functional/      # Functional requirements.
│   │   ├── non-functional/  # Non-Functional requirements.
│   ├── coding-style.md      # Coding-style guide.
│   ├── lessons-learned.md   # Non-obvious lessons learned.
│   ├── common-pitfalls.md   # Non-obvious pitfalls.
│   ├── testing.md           # Specifications for tests.
├── docs/                    # Explains the current implementation (generated by agent).
│   ├── architecture.md      # Description of the actual architecture.
│   ├── glossary.md          # Glossary with domain and technical terms.
├── adr/                     # Architecture Decision Records.
├── tasks/                   # Incremental work to be done.
├── packages/                # Generated source code.
├── prompts/                 # Promp templates.
├── tests/                   # Cross-package Integration and end-to-end tests.
└── scripts/                 # Developer utilities. Build, lint and automation scripts.
```

## Instructions

- Follow specifications from `specs/` folder with status `approved`.
- `docs/` folder and subfolders do not contain any specifications, it is documentation generated after building.
- →
- Track work as files under `tasks/` (move between the workflow stages).
- Capture non-obvious learnings in `docs/lessons-learned.md` and `docs/common-pitfalls.md`.

- When executing a task:

  1. Read the task in `tasks/backlog/`.
  2. Move it to `tasks/implementing`.
  3. Read any referenced specifications in `specs/`.
  4. Read any referenced ADRs in `adr/`.
  5. Identify the affected package(s).
  6. Implement the smallest change that satisfies the task.
  7. Run the validation commands.
  8. Move the task to `tasks/review`.
